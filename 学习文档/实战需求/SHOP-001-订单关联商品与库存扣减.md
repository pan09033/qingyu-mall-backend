# SHOP-001：订单关联商品与库存扣减

## 1. 需求背景

当前订单只保存商品名称，无法通过数据库外键确定订单对应的真实商品。
创建订单时还必须验证商品和库存，并保证“创建订单”和“扣减库存”同时成功或同时失败。

## 2. 用户故事

作为已登录用户，我希望通过商品编号和购买数量创建订单，以便系统准确识别商品并正确扣减库存。

## 3. API 契约

### 创建订单

```http
POST /orders/
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求体：

```json
{
  "product_id": 1,
  "quantity": 2
}
```

创建成功：`201 Created`

```json
{
  "id": 10,
  "product_id": 1,
  "product_name": "机械键盘",
  "quantity": 2,
  "user_id": 3
}
```

## 4. 数据库要求

`orders` 表新增字段：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `product_id` | 整数 | `NOT NULL`、外键 | 引用 `products.id` |

需要保留 `product_name`，它表示用户下单时的商品名称快照。商品以后改名时，历史订单名称不跟随变化。

当前开发数据库没有历史订单，因此 `product_id` 可以直接设置为非空字段。

## 5. 业务规则

1. 必须登录后才能创建订单。
2. `product_id` 必须大于或等于 1。
3. `quantity` 必须大于或等于 1。
4. 商品不存在时不能创建订单。
5. 商品库存不足时不能创建订单。
6. 创建成功后，库存减少本次购买数量。
7. 订单必须保存当前登录用户的编号，不能接受客户端传入 `user_id`。
8. 订单必须保存商品编号及下单时的商品名称。
9. 创建订单和扣减库存必须处于同一个数据库事务中。
10. 发生数据库错误时必须回滚事务。

## 6. 错误响应

| 场景 | 状态码 | `detail` |
|---|---:|---|
| 未提供有效 Token | 401 | 认证错误信息 |
| 商品不存在 | 404 | `商品不存在` |
| 库存不足 | 409 | `商品库存不足` |
| 参数范围不合法 | 422 | Pydantic 校验信息 |
| 数据库保存失败 | 500 | `订单保存失败` |

库存不足不是资源不存在，因此应使用 `409 Conflict`，不能使用 `404 Not Found`。

## 7. 验收标准

- [ ] `orders.product_id` 已通过 Alembic 迁移加入数据库。
- [ ] `orders.product_id` 外键指向 `products.id`。
- [ ] 创建订单的请求体只接收 `product_id` 和 `quantity`。
- [ ] 创建成功的响应包含 `product_id`。
- [ ] 创建成功后商品库存正确减少。
- [ ] 商品不存在时不创建订单，库存不变化。
- [ ] 库存不足时不创建订单，库存不变化。
- [ ] 未登录用户不能创建订单。
- [ ] 自动化测试全部通过。
- [ ] Alembic 检查不再存在未生成的模型变更。

## 8. 本次不做的内容

- 一个订单包含多个商品。
- 支付功能。
- 取消订单后恢复库存。
- 商品并发抢购和行级锁。
- 发货、退款等完整订单状态流转。

这些内容将在后续需求中逐步增加。
