# AUTH-001：当前用户修改密码

## 1. 需求背景

当前项目支持用户注册和登录，但用户注册后不能修改密码。
需要为已登录用户提供修改本人密码的接口。

## 2. 用户故事

作为已登录用户，我希望验证当前密码后设置新密码，以便在密码可能泄露或需要定期更换时保护账号。

## 3. API 契约

### 修改当前用户密码

```http
PATCH /auth/me/password
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求体：

```json
{
  "current_password": "abc123456",
  "new_password": "newPassword123"
}
```

修改成功：

```http
204 No Content
```

成功响应没有 JSON 响应体。

## 4. 数据规则

| 字段 | 类型 | 规则 |
|---|---|---|
| `current_password` | 字符串 | 长度 6～128 |
| `new_password` | 字符串 | 长度 6～128 |

## 5. 业务规则

1. 必须登录后才能修改密码。
2. 只能修改当前登录用户自己的密码。
3. 客户端必须提交当前密码和新密码。
4. 当前密码必须与数据库中的密码哈希匹配。
5. 新密码不能与当前密码相同。
6. 数据库中只能保存新密码的哈希，不能保存明文密码。
7. 修改成功后，旧密码不能再登录，新密码可以登录。
8. 响应和日志中都不能出现明文密码或密码哈希。
9. 数据库保存失败时必须回滚事务。

## 6. 错误响应

| 场景 | 状态码 | `detail` |
|---|---:|---|
| 未登录或 Token 无效 | 401 | 认证错误信息 |
| 当前密码错误 | 400 | `当前密码错误` |
| 新密码与当前密码相同 | 409 | `新密码不能与当前密码相同` |
| 请求字段缺失或长度不合法 | 422 | Pydantic 校验信息 |
| 数据库保存失败 | 500 | `密码修改失败` |

## 7. 验收标准

- [ ] 新增修改密码的 Pydantic 请求模型。
- [ ] 新增 `PATCH /auth/me/password` 接口。
- [ ] 接口通过依赖注入取得当前登录用户和数据库会话。
- [ ] 当前密码错误时返回 400。
- [ ] 新旧密码相同时返回 409。
- [ ] 新密码经过哈希后保存。
- [ ] 修改成功返回 204，且没有响应体。
- [ ] 修改成功后旧密码登录失败。
- [ ] 修改成功后新密码登录成功。
- [ ] 未登录调用接口返回 401。
- [ ] 自动化测试全部通过。
- [ ] 本需求不产生 Alembic 迁移。

## 8. 本次不做的内容

- 忘记密码和找回密码。
- 邮件或短信验证码。
- 强制其他设备退出登录。
- JWT 黑名单和 Token 撤销。
- 密码复杂度评分。
