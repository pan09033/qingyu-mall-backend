# 青屿商城演示与讲解路线

本项目适合展示 Python 后端接口、数据库事务、缓存、消息处理及 AI 应用接入的学习实践。演示围绕真实页面和接口展开。

## 启动与账号

配套前端源码目前为私有；公开访客可以先查看首页截图或运行后端 `/docs` 接口。已有前端源码时，按 [README](../README.md#本地演示) 启动两个进程。后端固定为 `127.0.0.1:8101`，前端为 `127.0.0.1:5174`，端口被占用时先关闭已有的演示进程。

Linux/macOS 的前端启动命令：

```bash
npm ci
VITE_API_BASE_URL=http://127.0.0.1:8101 npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

| 身份 | 入口 | 账号 | 演示密码 |
| --- | --- | --- | --- |
| 用户 | `/login` | `support_demo` | `DemoOnly123!` |
| 管理员 | `/admin/login` | `support_admin` | `DemoOnly123!` |

可在两个独立浏览器会话中分别登录用户和管理员。使用同一个会话时，先退出当前账号再切换角色。

## 三分钟展示顺序

1. **商品首页，约30秒**：展示分类和搜索，打开商品详情，说明前端通过 API 读取商品数据。
2. **订单与后端，约45秒**：查看已有订单，在代码中指向事务、行锁及幂等键的位置，说明订单到期消息和库存回补的设计。
3. **客服，约60秒**：进入客服页面，先问“订单支付后可以修改地址吗？”，展示资料来源；再问“查一下我的订单1”，展示按登录身份读取订单。
4. **人工工单，约45秒**：发送“转人工”，切换管理员查看工单、回复并标记解决，再回用户会话刷新查看结果。

这些动作只用于展示功能流程。讲解时应明确自己完成、修改或能独立解释的部分。

## 演示模式的范围

- 商品、用户和订单均为虚构数据，存储在内存 SQLite 中，进程结束后清空。
- 商品封面为本项目绘制的简单 SVG 示意图，不是实际商品照片。
- 页面、HTTP 路由、权限判断、数据库读写、客服会话和工单流程使用项目代码。
- 知识问答是固定演示结果；真实 BGE 检索和 DeepSeek 生成须使用完整环境验证。
- Redis 调用使用模拟对象；演示不启动 RabbitMQ、Outbox 消费任务和 MinIO。因此不要用本演示宣称缓存命中率、消息可靠性或并发性能。
- 演示不提供真实支付和退款。完整项目中的本地模拟支付也不代表接入第三方支付。
- 不读取开发者 `.env`，所有外部服务地址和凭据均在演示进程中覆盖为不可用于生产的本地值。

## 面试时可展开的实现

| 话题 | 建议阅读 | 能解释的问题 |
| --- | --- | --- |
| 接口分层 | `app/routers`、`app/services`、`app/repositories` | 参数校验、业务规则与数据库访问分别在哪里？ |
| 订单事务 | `app/services/order.py` | 为什么要加行锁？重复请求如何处理？失败时如何回滚？ |
| 商品缓存 | `app/product_cache.py` | 缓存未命中、数据修改和缓存重建怎么处理？ |
| 消息处理 | `app/services/outbox.py`、`app/mq` | 数据库提交和消息发送如何衔接？重复消费如何避免重复回补？ |
| 客服权限 | `app/services/support_tools.py` | 怎样限制查询本人订单？怎样避免把订单敏感字段传给模型？ |
| 知识回答 | `app/rag/services/grounded_qa.py` | 如何验证引用？资料不足时怎样处理？ |

## 停止与恢复

在前后端两个终端分别按 `Ctrl+C`。重新运行后端演示命令即可恢复最初的演示商品和账号，无须删除真实数据库或容器。
